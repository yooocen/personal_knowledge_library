# BM25 检索原理

关联笔记:[[第1章-向量引论]]、[[机器学习]]、[[LLM疑云]]、[[智普大模型]]、[[deepseek]]

> 一句话:**BM25 = IDF × 饱和词频 × 长度归一化**,搜索引擎几十年的"标配",稀疏检索的事实标准,也是稠密向量检索必须超越的强力基线。

---

## 1. 是什么

**BM25 (Best Matching 25)** 是基于**概率相关模型(Probabilistic Relevance Model)** 的全文检索排序函数,由 Robertson 与 Walker 等人在 1990 年代提出。它是搜索引擎领域**事实上的标准排序算法**,广泛应用于:

- **Lucene / Elasticsearch / Solr** 的默认打分(经工程化改造)
- 通用搜索引擎的排序基线
- **RAG(Retrieval Augmented Generation)** 中稀疏检索(sparse retrieval)的经典基线

"BM" = Best Matching,"25" 是 Robertson 一系列 BM 公式中的第 25 号参数设定——这套设定在实践中效果最好,于是固定下来。

---

## 2. 核心公式

给定查询 $Q$(含词项 $q_1, q_2, \dots, q_n$)与文档 $D$,BM25 计算 $D$ 对 $Q$ 的相关性得分:

$$
\mathrm{score}(D, Q) = \sum_{i=1}^{n} \mathrm{IDF}(q_i) \cdot \frac{f(q_i, D) \cdot (k_1 + 1)}{f(q_i, D) + k_1 \cdot \left(1 - b + b \cdot \dfrac{|D|}{\mathrm{avgdl}}\right)}
$$

| 符号 | 含义 |
|------|------|
| $f(q_i, D)$ | 词项 $q_i$ 在文档 $D$ 中出现次数(词频 TF) |
| $\|D\|$ | 文档 $D$ 长度(词项数) |
| $\mathrm{avgdl}$ | 语料库文档平均长度 |
| $k_1$ | 词频饱和参数(常用 1.2 ~ 2.0) |
| $b$ | 文档长度归一化参数(常用 0.75) |
| $\mathrm{IDF}(q_i)$ | 词项 $q_i$ 的逆文档频率 |

**IDF 公式(Lucene 实践版本,加 $1+$ 保证非负)**:

$$
\mathrm{IDF}(q_i) = \ln\left(1 + \frac{N - n(q_i) + 0.5}{n(q_i) + 0.5}\right)
$$

- $N$:语料库文档总数
- $n(q_i)$:包含 $q_i$ 的文档数

---

## 3. 三大核心直觉

BM25 可拆成"三根支柱",每根都在解决朴素计数带来的问题。

### 3.1 词频饱和(TF Saturation)

- **朴素做法**:词出现越多越相关。问题——出现 100 次与 50 次的文档相关性真差两倍吗?
- **BM25 处理**:分子分母同含 $f$,使函数随词频增长**趋于上界**(类双曲函数)。出现第 1 次贡献大,第 100 次几乎无增量。
- **参数 $k_1$** 控制饱和速度:$k_1$ 越大,饱和越慢,词频越接近线性增长。

### 3.2 逆文档频率(IDF)

- **朴素做法**:出现次数越多越相关。问题——"的、了、是"这类高频词出现 100 次不代表更相关。
- **BM25 处理**:出现在越多文档里的词,$\mathrm{IDF}$ 越低;出现在少数文档里的稀有词,$\mathrm{IDF}$ 高、信息量大。
- Lucene 版加 $1+$ 避免极端情况(词出现在几乎所有文档)下出现负 $\mathrm{IDF}$。

### 3.3 文档长度归一化

- **朴素做法**:长文档天然词频偏高,得分会"虚高"。
- **BM25 处理**:用 $\|D\|/\mathrm{avgdl}$ 把当前文档长度和平均长度对比,长文档会被**降权**。
- **参数 $b$** 控制降权强度:
  - $b = 0$:完全不考虑长度
  - $b = 1$:完全按长度线性归一化
  - $b = 0.75$:经验最优,长文档适度降权

---

## 4. 与 TF-IDF 的对比

| 维度 | TF-IDF | BM25 |
|------|--------|------|
| 词频 | 线性(越多越好) | 饱和(边际递减) |
| 长度归一 | 无 | 有($b$ 控制) |
| 参数 | 无 | $k_1, b$ 可调 |
| 理论基础 | 向量空间 / 启发式 | 概率相关性模型 |

**一句话理解**:BM25 = TF-IDF + 词频饱和 + 长度归一化,且有理论支撑、参数可调。

---

## 5. 参数怎么调

- **$k_1 \in [1.2, 2.0]$**,默认 $1.2$。语料词频分布陡峭(短文档居多)调小;长文档 / 重复词多调大。
- **$b \in [0, 1]$**,默认 $0.75$。文档长度差异大、长文档噪声多调大;长度均匀或专业术语密集调小。

工程上 90% 的场景用默认 $(1.2, 0.75)$ 就够好。中文短查询(2~3 字)词频本就低,$k_1$ 影响变小,此时调 $b$ 收益可能更明显。

---

## 6. 局限性

1. **词袋模型(Bag-of-words)**:忽略词序、语法、近邻关系。改进方向:**BM25F**(字段加权)、**BM25 Proximity**(近邻)。
2. **词法匹配**:query 词与 doc 词必须字面 / 词干重叠,"汽车"匹配不到"轿车"。
3. **OOV 问题**:未见过的词 $\mathrm{IDF}$ 估计不准。
4. **无语义理解**:不懂同义、上下文、意图。

正因如此,近年**稠密检索(dense retrieval,如 DPR、向量检索)** 兴起,试图用 embedding 捕捉语义。但大量基准(如 **BEIR / MTEB**)反复表明:**未经微调的稠密检索在很多领域并不稳定优于 BM25**,且 BM25 无需训练数据、可解释、无模型部署成本。实际系统多采用 **混合检索(BM25 + 向量)→ RRF / 加权融合**。

## 7. 极简可运行示例(Python)

手写 BM25,跑一个 5 文档的小语料,打印每篇的 TF / IDF / 最终得分,比纯公式更直观。

```python
import math
from collections import Counter

# 1) 准备语料(已分词)
docs = [
    "the cat sat on the mat".split(),
    "the dog sat on the log".split(),
    "cats and dogs are friends".split(),
    "the quick brown fox jumps".split(),
    "a quick brown dog runs fast".split(),
]
query = "quick brown dog".split()

# 2) 基础统计
N = len(docs)
avgdl = sum(len(d) for d in docs) / N
df = Counter()               # 每个词出现在多少篇文档
for d in docs:
    for w in set(d):
        df[w] += 1

# 3) BM25 参数
k1, b = 1.2, 0.75

def idf(term):
    n_qi = df.get(term, 0)
    return math.log(1 + (N - n_qi + 0.5) / (n_qi + 0.5))

def bm25(doc, query, k1=1.2, b=0.75):
    score = 0.0
    tf = Counter(doc)
    dl = len(doc)
    for q in query:
        f = tf.get(q, 0)
        num = f * (k1 + 1)
        den = f + k1 * (1 - b + b * dl / avgdl)
        score += idf(q) * (num / den if den else 0)
    return score

# 4) 打分排序
ranked = sorted(enumerate(docs), key=lambda x: bm25(x[1], query), reverse=True)
for idx, doc in ranked:
    print(f"doc{idx}  score={bm25(doc, query):.4f}  {' '.join(doc)}")
```

预期:含 `quick brown dog` 三词的文档 4 得分最高,文档 3(`the quick brown fox jumps`)因含 `quick` `brown` 次之,体现了"词频饱和 + 长度归一"的效果。

---

## 8. 局限与边界(对抗性审查)

- **关键假设**:BM25 假设"词项独立 + 词频饱和 + 文档长度需归一"。这三条是经验归纳,在中文短查询上词频饱和作用有限。
- **"被深度学习超越"的质疑**:但 BEIR / MTEB 等零样本基准反复表明,**未微调的稠密检索在很多领域并不稳定优于 BM25**,数据稀缺场景 BM25 仍是首选。
- **实现差距**:严格说 Lucene 用的是 BM25 的近似变体(用 `docFreq` 近似、跳过低频项打分优化),线上"默认打分"与教科书公式有工程差距,不能 1:1 对照公式看行为。
- **失败条件**:查询词全部未在文档中出现(OOV)、或查询为语义型问题("怎么解决焦虑")而非事实检索型问题时,BM25 几乎失效。
- 参数经验值 $(1.2, 0.75)$ 是经验最优而非理论最优,需按语料验证。

---

## 9. 一句话总结

> BM25 = IDF × 饱和词频 × 长度归一化。简单、可解释、可调参,稀疏检索的事实标准,稠密检索必须超越的强力基线。
