# 项目级规则

## L0 → L1 总结规则

### 概述

将 `L0` 目录下的会话记录总结为精炼摘要，写入 `L1` 目录。**仅当用户明确要求总结时执行**，不自动触发。

### 目标目录

- **L0 根**: `agents\L0`
- **L1 根**: `agents\L1`

### 执行时机

**仅在用户明确要求总结时执行**，不自动触发。任何轮次开始时都不应主动检查或执行 L0→L1 总结。

### 变动检测机制

通过比较 L0 文件列表及文件的最后修改时间来判断是否有变动。每次总结完成后记录当前 L0 文件快照供下次比对。

### 总结步骤

1. 扫描 `L0` 目录下所有子目录（按项目名称组织），列出所有 `.md` 文件。
2. 对于每个**尚未在 L1 中有对应总结文件**的会话记录（通过解析 L1 文件内的"源文件"超链接判断对应关系，而非文件名比对），执行总结。
3. 总结内容包括：
   - 会话时间与项目归属
   - 关键决策与结论
   - 有长期价值的技术见解、架构决策、设计模式
   - 重要的问题解决方案与思路
   - 未来行动项或待办事项
   - 重大学到的知识点
4. 总结尽可能精简（每份会话记录不超过 100 行 markdown），保留可操作价值。

### 输出格式

- **L1 文件名**: 用该会话的**具体一句话摘要**作为 `.md` 文件名（不再沿用 L0 的 `YYYY-MM-DD_HH-mm-ss_<session-id>.md` 命名）。摘要需清理为合法 Windows 文件名：去除 `\ / : * ? " < > |` 等非法字符，去除首尾空格与点，建议不超过 60 字符，空格可保留。若与同项目下已有 L1 文件重名，在末尾追加 `(2)`、`(3)` 等序号。
- **文件位置**: 仍放在与 L0 同名的项目子目录下（`L1/<项目>/<摘要>.md`）。
- **H1 标题**: 文档首个 `#` 标题与文件名一致（同为该会话的一句话摘要），或稍作展开补副标题。不得使用"会话总结"等泛化标题。
- **源文件超链**: 在 H1 下方元信息区用 Markdown 链接指向 L0 源文件（L0 仍保留 `YYYY-MM-DD_HH-mm-ss_<session-id>.md` 原命名），链接文本为 L0 源文件名，目标用相对路径 `../../L0/<项目>/<文件名>.md`。格式示例：
  `**源文件**: [2026-07-24_10-48-57_<session-id>.md](../../L0/codex/2026-07-24_10-48-57_<session-id>.md)`
  由于 L1 文件名不再与 L0 同名，L0↔L1 的对应关系完全由该超链接承担。
- **_index.md**: 如果某项目文件夹下已有多个总结文件，另生成一个 `_index.md` 作为该项目所有会话的目录索引，每行列出会话时间、摘要（作为链接文本指向对应 L1 文件）和关键标签。
- 删除 `L1` 中对应的过时会话总结（L0 中已删除的文件）。

### 注意事项

- 不要将凭据、密钥或敏感信息写入 L1 总结文件。
- 总结要保留技术准确性，不要过度简化导致信息失真。
- 如果 L0 某文件内容未变且 L1 中已有指向它的总结（通过源文件超链接定位），则跳过。
